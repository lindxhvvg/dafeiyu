# 实体准入门槛 · 形态分层与验收清单

建档：2026-11-14。这份文档回答两个问题：本地系统要完善到什么程度才值得往实体搬；"像微信里一个真人"与"真正互动"是不是同一件事。

## 0. 先澄清"线上"这个词

**可验证事实**：2026-11-08，曾有一个公开链接提供页面访问，其中带着 API 密钥与记忆库；我把它下线了。2026-11-14 18:14 实测，三个服务端口都不可达，系统启动文件夹里只有 `desktop.ini`。

**设计判断（未经实测）**：需要补齐的是"通道常驻"，不是"把记忆搬上云"。记忆留在本地 SQLite 文件里，通道可以是本机常驻，也可以是托管中继；这两件事是彼此独立的决定。把两者混为一谈，会重演上面那次密钥暴露。

## 1. 三层形态（L 分层）

| 层 | 含义 | 小飞鱼现状 |
|---|---|---|
| **L1 对话** | 你问她答，文字与语音都能用 | 已具备：三脑路由、TTS、逐字字幕、回声窗、噪声守门 |
| **L2 在场** | 她一直在、会主动找你、状态可见、消息能送到你手边 | 部分具备：主动搭话、「想起」、提醒推送器（实测 18.6 秒送达）、`/monitor`；缺服务常驻、手机通知、双工语音 |
| **L3 物理互动** | 她感知房间里的光与人声、转头看你、用身体动作表达、能操作现实物件 | 未开始。ACT 状态机是行为规划器原型，架构文档把它列为 v3 |

**设计判断（未经实测）**：微信感属于 L2，实体身体属于 L3，两者不是二选一。L2 的关键不是模型更聪明，而是四件事——通道常驻、主动发起、状态可见、双工连续。这四项里目前只有"主动发起"比较完整。

## 2. 准入门槛（G 编号，可逐条验收）

| 编号 | 项目 | 现状（实测或文档记录） | 达标线 | 验证方法 |
|---|---|---|---|---|
| **G1** | 服务常驻 | 2026-11-14 18:14 实测：8765 / 8080 / 11434 全灭；启动文件夹无自启项 | 连续 7×24 小时无需人工干预，在线率可查 | `/monitor` 服务健康三灯 + 看门狗运行日志 |
| **G2** | 主动发起 | 已有 proactive、daydream「想起」、提醒推送器（18.6 秒实测送达） | 一天内主动发起可计数，送达率可查 | `/monitor` 提醒送达记录 + `recent_recalled` |
| **G3** | 状态可达 | `/monitor` 仅本机浏览器可看；局域网模式已建，但需手动开浏览器、无通知 | 任意设备打开即见，无需操作 | 手机扫码后直接打开监测台 |
| **G4** | 双工语音 | 回合制；回声窗、噪声守门、打断协议是补丁 | 可随时打断、不吞字、通话连续 | 真实通话压测（**未做**） |
| **G5** | 记忆连续性 | 本地 SQLite；日记连续 9 份；跨重启补写已实测 | 换设备与重启后人格、记忆都不丢 | 换设备读取验证（**未做**） |
| **G6** | 断网生存 | ollama 与 qwen2.5-7B 已装机，独立首答实测 17.7 秒 | 真实断网后全链可用 | 拔网压测（**未做**） |
| **G7** | 成本与隐私 | `token_ledger` 按天按脑记账；白名单静态服务九例防泄密实测通过 | 账单可查，密钥不出局域网 | `/monitor` 账单 + 白名单回归 |
| **G8** | 故障可归因 | 服务端 `dbg.log` 与客户端 `clog` 回传已成对 | 一次异常能定位到具体环节 | 双端时间线对账 |

### 硬门槛

**G1 / G5 / G7** 是硬门槛。**设计判断（未经实测）**：这三项不达标时，实体设备分别会变成"找不到人的盒子""失忆的盒子""漏密钥的盒子"，加硬件补不回来。其余五项是体验门槛，可以边用边补。
